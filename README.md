# Desafio Departamental - Projetos | Visão Júnior

Este repositório contém a entrega final para o Desafio Departamental do Departamento de Projetos (Programa Trainee) da empresa júnior Visão Júnior[cite: 1]. 

O projeto simula um ambiente de desenvolvimento ágil, focando na resolução de problemas recorrentes de versionamento, estruturação de repositório e colaboração de código[cite: 1].

## 🎯 Objetivo
Demonstrar na prática o domínio sobre ferramentas de versionamento e propor uma rotina de trabalho segura utilizando o GitHub[cite: 1], executando o ciclo de vida completo do Git (Clone, Branch, Add, Commit, Push, Pull Request e Merge)[cite: 1].

## 🛠️ Tecnologias e Ferramentas Utilizadas
- **HTML5:** Estruturação semântica da página.
- **CSS3:** Estilização, layout flexível (Flexbox) e responsividade.
- **Git & GitHub:** Versionamento de código e hospedagem.
- **GitHub Projects & Issues:** Gestão ágil das tarefas utilizando kanban[cite: 2].

## 🚀 Funcionalidades Desenvolvidas
O desenvolvimento foi dividido em etapas incrementais, simulando demandas reais[cite: 2]:
- **[TASK-01] Página Principal:** Estrutura inicial com layout configurado e uma caixa de conteúdo centralizada (60% de altura, margem de 24px)[cite: 2].
- **[TASK-02] Header:** Cabeçalho com logo interativa que reinicia a página ao ser clicada[cite: 2].
- **[TASK-03] Footer:** Rodapé com estilização própria fixado ao final da página contendo a menção de direitos reservados[cite: 2].

## 🔄 Fluxo de Trabalho (Git Flow)
Para garantir um histórico de alterações limpo e evitar a sobrescrita acidental de arquivos[cite: 1], o projeto seguiu um fluxo de revisão rigoroso:

1. **Branches Isoladas:** Nenhuma alteração foi feita diretamente na `main`. Todo o desenvolvimento partiu da branch `dev`[cite: 1].
2. **Ramificação por Funcionalidade:** Cada task gerou uma nova branch seguindo o padrão de nomenclatura exigido (ex: `task/01-pagina-principal`)[cite: 1].
3. **Commits Semânticos:** Utilização de mensagens claras e padronizadas para facilitar a rastreabilidade[cite: 1].
4. **Revisão e Merge em Etapas:** Abertura de Pull Requests individuais de cada task para a branch `dev`, simulando um processo de *Code Review*[cite: 1, 2].
5. **Integração Segura:** Apenas após a conclusão e validação de todo o backlog na `dev`, um Pull Request definitivo foi aberto e integrado à branch `main`[cite: 1].
